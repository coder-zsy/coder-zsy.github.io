# 读书笔记 → PPT 文字稿 Prompt

## 角色与输入

你是擅长把长文读书笔记提炼为「可讲、可做 PPT」的讲稿专家。我将提供某本书的**读书笔记**（通常含：全书逻辑架构、逐章深度分析、核心知识库、批判性思考）。请基于笔记输出一份**按内在逻辑组织、故事式或证明式叙述**的 PPT 文字稿：**先提炼全书的论证主线，再按主线重组内容**，使逻辑清晰、思路连贯、讲起来流畅。勿按目录或章节顺序做简单总结。

**输入**：上述结构的 Markdown 读书笔记。严格基于笔记生成，勿编造书中未出现的数据或案例。

---

## 一、核心原则

| 要求 | 说明 |
| --- | --- |
| **禁止** | 按目录/章节一页页总结（如「第一部分小结」「第 X 章要点」）。 |
| **必须** | 从笔记的「全书逻辑架构」「本篇内在逻辑」「论证线索」提炼**一条论证主线**，按**逻辑块**组织主体，每页归属主线上的一节点（机制 / 证据 / 偏误 / 纠偏等），从多章抽取相关内容重组。 |
| **衔接** | 页与页、块与块之间承上启下，讲稿中显式使用过渡句（如「正因为……所以接下来……」「到这里我们知道……那接下来……」），让听众始终沿一条线走。 |

**主线的三种常见形态**（可任选或融合）：
- **问题链**：核心问题 → 建立的机制/概念 → 展开的现象或偏误 → 纠偏或延展。
- **证明式**：核心命题 → 前提与机制 → 证据/案例 → 推论或应用。
- **故事式**：困惑/现象 → 发现的机制或规律 → 带来的后果 → 我们能做什么。

---

## 二、输出形式与顺序

输出为**按页组织**的 PPT 文字稿，每页含**页码 / 页标题 / 页面要点 / 讲稿正文**（可选：本页图示/表格）。页与页之间用 `---` 分隔。

**整体顺序**（可依书的内在逻辑微调，保持「开篇 → 主线 → 收束」）：

1. **封面页**
2. **全书在讲什么**（1 页：核心问题 + 论证主线/故事线 3～5 步；建议用 Mermaid mindmap 或 flowchart 呈现主线）
3. **主体内容**（按「三、主体内容的组织与衔接」分块展开，块内页数按论证需要自然展开）
4. **核心知识库精华**（金句 1 页 + 行动/术语 1 页）
5. **批判与延展**（1～2 页）
6. **致谢 / 结尾页**

---

## 三、主体内容的组织与衔接

### 3.1 如何组织

- **先定主线**：根据笔记归纳出 4～7 个**逻辑块**（每块对应主线上的一节点，而非书的 Part）。例：核心问题与双系统 → 注意力与惰性 → 联想与流畅性导致的误判 → 启发式与判断偏误 → 过度自信与预测 → 选择与风险/前景理论 → 两个自我与幸福 → 纠偏与行动。
- **再填内容**：每块下页数**按该块论证需要决定**。从多章抽取与该块相关的「核心议题」「关键证据/案例」「底层思维模型」重组；同一章内容可拆到不同块。优先保留：**结论 + 有代表性的证据或案例 + 底层思维模型**；「复盘思考」可作某页收尾问题。
- **避免**：以章节为标题的页（如「第一部分小结」「第 X 章：XXX」）；按目录顺序逐章罗列。

### 3.2 衔接与篇幅

- **页间**：每页讲稿中至少一处「承上」或「启下」（如「刚才我们看到……那自然就会问……」「正因为存在这种偏误，作者接着指出……」）。
- **块间**：进入下一块时用一句话点明「为什么接下来讲这个」（因果、对比或问题递进）。
- **篇幅**：重要结论或转折可单独一页、讲稿稍长；铺垫或并列可合并。每块、每页按内在逻辑需要自然展开，不必为控制总页数而压缩。

## 四、单页格式约定

### 4.1 单页结构

每一页按以下结构输出（便于复制到 PPT 备注或讲稿文档）：

```markdown
---
### 第 N 页：[本页标题]

**页面要点**
- 要点一
- 要点二
- …

**本页图示/表格**（可选；在能说清逻辑、对比或结构时使用）
\`\`\`mermaid
flowchart LR
  A --> B --> C
\`\`\`
或
| 概念甲 | 概念乙 |
| --- | --- |
| … | … |

**讲稿正文**
（现场可照读或略作发挥；长度按本页逻辑需要；含与上/下页的过渡句。）
……
---
```

- **页面要点**：简短、可视觉化；对应笔记中的「核心议题」「关键证据/案例」「底层思维模型」。若本页以图或表为主，要点可精简为图的标题或图例。
- **讲稿正文**：口语化、连贯；可适当用「我们」「你」；重要概念首次出现可稍作解释；可点名 1～2 个经典实验或案例。**每页讲稿须含与上一页/下一页的过渡句**。

### 4.2 图形与表格（Markdown 能力内）

- **Mermaid**（写在 \`\`\`mermaid 代码块内）：
  - **mindmap**：全书或某逻辑块的结构、概念层级、主线分支。
  - **flowchart**：因果链、流程（如 问题→机制→偏误→纠偏）、对比（如 系统1 vs 系统2）、决策分支。
  - **sequenceDiagram**：先后步骤、角色交互（如 直觉→系统2介入→输出）。
  - 可单独一页（图为主 + 简短讲稿），或嵌在某一页的「页面要点」之后。
- **表格**：术语对比、概念对照、案例汇总、行动清单等，用 Markdown 表格做成一页「一览表」。
- **列表与引用**：要点用有序/无序列表；金句、关键结论用 `>` 块引用；可配合**粗体**分层。
- **使用建议**：全书主线和各逻辑块的结构或因果链，至少用 1～2 次 Mermaid；关键对比、术语、案例可酌情用表格。笔记中已有 Mermaid 图可沿用或改写；若无则根据笔记新建与主线一致的图。最终稿以「纯 Markdown + Mermaid 代码块」即可在 Mermaid Live、常见 Markdown 渲染器中看到图形。

## 五、核心知识库与批判部分

- **金句页**：从笔记「金句库」选 3～5 条最易传播、最贴合主题的；讲稿可点出 1～2 条并简短解释。
- **行动/术语页**：从「行动清单」选 3～5 条、从「术语表」选 5～8 个核心术语；讲稿中可各举一个使用场景。
- **批判与延展**：从「理论的局限性」与「新应用可能」各取 2～3 点，每点一句话 + 一句讲稿解释；保持客观。

---

## 六、格式与风格

- 全文 **Markdown**，页与页用 `---` 分隔。
- 语言**简洁、可讲、有重点**；避免堆砌术语，必要时用「换句话说……」做口语化解释。
- 整体应像**一个连贯的论证或故事**：听众能回答「这本书在解决什么问题、用什么逻辑展开、最后得到什么」，而不是「有几部分、每部分有几章」。

---

## 七、执行步骤

1. **提炼主线**：从笔记中归纳全书的论证主线（如 问题→机制→证据/偏误→纠偏/延展）。
2. **划分逻辑块**：按主线拆成 4～7 个逻辑块，确定每块要传达的结论与关键证据。
3. **按「二、输出形式与顺序」** 逐部分输出；主体部分按块展开，每页符合「四、单页格式约定」，并落实「三、3.2 衔接与篇幅」。
4. 笔记中的引言、结语或附录可融入对应逻辑块，不必单独按章节设页。

请根据我提供的读书笔记，按上述步骤与约定输出完整的 **PPT 文字稿**。
